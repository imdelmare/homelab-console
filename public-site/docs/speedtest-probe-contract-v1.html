Speedtest Probe contract v1 ​

Scope ​

The probe runs one fixed, operator-supplied Ookla Speedtest CLI binary. It has no generic command, arguments, scheduling or caller-selected server. The binary is separately licensed, gitignored and must never be included in public source or redistributed images without authorization.

HTTP API ​

GET /health ​

Unauthenticated response:

http
200 {"status":"ready"}
200 {"status":"busy"}
1
2

Other GET paths return 404 {"error":"not_found"}.

POST /v1/tests/run ​

Requires Authorization: Bearer <token> and an empty request body. The token must be configured and is compared in constant time.

Success returns 200:

packet_loss_percent and result_url may be null. Bandwidth is Mbps converted from CLI bytes/second. The allowlisted response never includes public/local IPs or raw CLI payloads.

Error matrix:

StatusBody
400{"error":"request_body_not_allowed"}
401{"error":"unauthorized"}
404{"error":"not_found"}
409{"error":"test_in_progress"}
502{"error":"speedtest_failed","kind":"..."}
504{"error":"speedtest_timeout"}

kind is diagnostic and clients must not branch on its value. One non-blocking global lock permits only one test at a time.

Execution and core integration ​

The exact command is:

text
/opt/speedtest-cli/speedtest --accept-license --accept-gdpr --format=json --progress=no
1

Probe timeout is clamped to 30–180 seconds. The core declares an inventory instance with driver speedtest_probe_v1, a fixed base URL and bearer token. It exposes only <instance_id>.speedtest.run, with empty input, medium risk and normalized output. Callers cannot select URL, server, command or arguments.

Compatibility and conformance ​

Compatible v1 implementations must test fixed command construction, bearer authentication, empty-body enforcement, normalized units/allowlist, concurrent 409, timeout 504, execution failure 502 and omission of sensitive CLI fields. Breaking paths, auth, units or response fields require v2.
